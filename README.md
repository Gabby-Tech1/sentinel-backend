# Sentinel Lab Backend

FastAPI backend for **Sentinel Lab**, a research dashboard supporting an AI-for-Cybersecurity Strategy Framework for developing countries. It serves cybersecurity scenarios, runs agent-driven experiments against a simulated local network, streams execution events, and stores results for analysis.

## Features

- **Scenario library:** seeded scenarios with network topologies, resource profiles, and ground-truth findings.
- **Agent execution:** a scripted stub agent for local experiments and an optional Claude agent through the Anthropic API.
- **Local target lab:** Python TCP/HTTP services that simulate service banners and vulnerable behavior on loopback addresses, with simulated latency and packet loss.
- **Live updates:** Server-Sent Events (SSE) for run snapshots, execution events, and completion status.
- **Research data:** persisted runs and metrics, thematic findings, and a strategy framework.
- **Interactive API documentation:** Swagger UI and ReDoc generated by FastAPI.

## Technology

| Component | Implementation |
| --- | --- |
| Runtime | Python 3.11+ |
| API server | FastAPI and Uvicorn |
| Validation and configuration | Pydantic and pydantic-settings |
| Persistence | SQLModel / SQLAlchemy; SQLite by default |
| Network tools | asyncio and HTTPX |
| Optional model integration | Anthropic Python SDK |
| Development | pytest, pytest-asyncio, Ruff |

## Quick start

Run these commands from the backend repository root, the directory containing `pyproject.toml`. If you have the combined project checkout, enter `backend` first.

### Windows (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

These commands use the virtual environment directly, so PowerShell activation is unnecessary. If `.venv` already exists, skip its creation.

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

For runtime dependencies only, use `pip install -e .` instead of the development extra.

### Verify the server

Open these URLs after startup:

| URL | Purpose |
| --- | --- |
| http://127.0.0.1:8000/health | Health check |
| http://127.0.0.1:8000/docs | Interactive Swagger UI |
| http://127.0.0.1:8000/redoc | ReDoc API reference |
| http://127.0.0.1:8000/openapi.json | OpenAPI schema |

The health endpoint returns:

```json
{"status":"ok","service":"sentinel-backend","version":"0.1.0"}
```

Press **Ctrl+C** in the server terminal to stop. `--reload` restarts the development server when source files change; omit it for uninterrupted experiments.

## Configuration

An optional `.env` file is loaded from the current working directory. Environment variables override values in that file. Local stub runs work without an API key or `.env` file.

Example `.env`:

```dotenv
DATABASE_URL=sqlite:///./sentinel.db
CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000

# Optional: set a real key locally to enable the Claude agent.
# ANTHROPIC_API_KEY=your-key-here
```

| Variable | Default | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | `sqlite:///./sentinel.db` | Database connection URL. The default file is relative to the working directory. |
| `CORS_ORIGINS` | `http://localhost:3000` | Comma-separated browser origins allowed to call the API. |
| `ANTHROPIC_API_KEY` | Unset | Enables construction of the Claude agent. Requires a valid key for successful model requests. |
| `USE_STUB_CAI` | `true` | Defined in settings but currently unused for agent selection. Choose the agent in `POST /runs`. |

Restart the backend after changing configuration. Keep API keys in the backend environment; `.env` is excluded by `.gitignore`.

### Agent selection

The `agent` field in `POST /runs` accepts:

- `stub` (default): follows scripted decisions and uses the local network tools; no model API key is required.
- `claude`: uses the configured Anthropic API key. An optional `model` field overrides the default defined in `app/agent/claude_agent.py`.

`GET /meta/capabilities` reports available agents and the configured default model. Claude availability in this response checks whether a key is present; it does not validate the key with Anthropic.

## API reference

Paths are relative to `http://127.0.0.1:8000`. See `/docs` for full request and response schemas.

| Method | Path | Description |
| --- | --- | --- |
| GET | `/health` | Service health and version |
| GET | `/meta/capabilities` | Agent availability and default model |
| GET | `/scenarios` | List scenarios |
| GET | `/scenarios/{scenario_id}` | Get a scenario |
| GET | `/runs` | List runs; optional `scenarioId` and `status` filters |
| POST | `/runs` | Start a run; returns HTTP 201 |
| GET | `/runs/{run_id}` | Get a run with its persisted events and metrics |
| POST | `/runs/{run_id}/cancel` | Cancel the active run |
| GET | `/runs/{run_id}/events` | Stream run updates through SSE |
| GET | `/findings` | List research findings; optional `theme` filter |
| GET | `/findings/{finding_id}` | Get a research finding |
| GET | `/framework` | Get the seeded strategy framework |
| GET | `/lab/status` | Inspect lab services and their status |
| POST | `/lab/{scenario_id}/start` | Start or switch the local target lab |
| POST | `/lab/stop` | Stop local target services |

Common errors include HTTP 404 for missing resources, HTTP 400 for an unsupported agent or missing Claude key, and HTTP 409 when another run is active or cancellation targets a non-active run. Invalid request data produces FastAPI validation errors (HTTP 422).

### Start a local experiment (PowerShell)

With the backend running, open another terminal:

```powershell
$apiBase = "http://127.0.0.1:8000"
Invoke-RestMethod "$apiBase/scenarios"

$runBody = @{
    scenarioId = "scn-recon-min-gov"
    agent = "stub"
} | ConvertTo-Json

$experiment = Invoke-RestMethod -Method Post -Uri "$apiBase/runs" `
    -ContentType "application/json" -Body $runBody

Invoke-RestMethod "$apiBase/runs/$($experiment.id)"
```

The orchestrator starts the scenario's lab when switching to that scenario. A run progresses asynchronously after the initial response. Only one run can be active at a time in the server process.

To cancel while it is active:

```powershell
Invoke-RestMethod -Method Post "$apiBase/runs/$($experiment.id)/cancel"
```

### Stream events

Use the returned run ID:

```bash
curl -N http://127.0.0.1:8000/runs/YOUR_RUN_ID/events
```

In Windows PowerShell, use `curl.exe -N` to invoke curl directly. The stream emits `snapshot` for persisted run state, `event` for new activity, and `done` for terminal status. Connecting to a completed run returns its snapshot followed by `done`.

### Use Claude

After setting `ANTHROPIC_API_KEY` and restarting the server, send this JSON to `POST /runs`:

```json
{
  "scenarioId": "scn-recon-min-gov",
  "agent": "claude"
}
```

Claude runs make external model requests using your Anthropic account. Add `"model": "YOUR_MODEL_ID"` to select a different supported model.

## Connect the frontend

In the Sentinel Lab Next.js frontend, create or update `.env.local`:

```dotenv
NEXT_PUBLIC_USE_REAL_API=true
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000
```

Restart the frontend development server after changing these values. Its browser origin must appear in the backend's `CORS_ORIGINS`. Without `NEXT_PUBLIC_USE_REAL_API=true`, the frontend uses its mock data mode.

## Deploy a free demo on Render

This repository includes `Dockerfile` and `render.yaml`. Docker provides Python
3.12 and runs one Uvicorn worker on Render's `PORT`. The container retains its
default root user because the simulated lab binds privileged ports on loopback.
Render exposes only the API HTTP port; the simulated lab stays inside the container.

### Create the service

1. Push the deployment files to the backend GitHub repository. This checkout's
   `main` branch tracks `Gabby-Tech1/sentinel-backend` (`newrepo`).
2. In the [Render dashboard](https://dashboard.render.com), choose **New > Blueprint**
   and connect that backend repository and its `main` branch.
3. Use `render.yaml` as the Blueprint path. The backend is its own repository,
   so do not set a `backend` root directory.
4. The Blueprint sets `CORS_ORIGINS` to `https://sentinal-lab.vercel.app`.
   If the frontend domain changes, update it to the exact origin without a trailing slash or URL path.
   For local development too, use
   `https://sentinal-lab.vercel.app,http://localhost:3000,http://127.0.0.1:3000`.
5. Confirm the service plan is **Free**, then deploy. No database service or disk
   is required. The service creates and seeds its SQLite database on startup.

Alternatively, choose **New > Web Service** with these settings:

| Setting | Value |
| --- | --- |
| Branch | `main` |
| Language | Docker |
| Root directory | Leave empty for the standalone backend repository |
| Dockerfile path | `./Dockerfile` |
| Instance type | Free |
| Health check path | `/health` |
| Docker command | Leave empty (uses the Dockerfile command) |
| `DATABASE_URL` | `sqlite:////app/sentinel.db` |
| `CORS_ORIGINS` | `https://sentinal-lab.vercel.app` |

There are no separate build/start commands to enter for the Docker runtime.
Automatic deploys are disabled in the Blueprint to avoid interrupting experiments.
After future pushes, use **Manual Deploy > Deploy latest commit**.

### Connect and verify

Copy the actual `https://...onrender.com` URL from Render. Set these variables in
the frontend hosting provider and rebuild/redeploy the frontend:

```dotenv
NEXT_PUBLIC_USE_REAL_API=true
NEXT_PUBLIC_API_BASE_URL=https://YOUR-SERVICE.onrender.com
```

Check `/health` returns `status: ok`, `/scenarios` returns six scenarios, and
`/docs` loads. From the frontend, start a **stub** experiment, watch its live
events, and confirm the saved result appears. Inspect `/lab/status` after starting
the experiment to check for failed service bindings in the Linux container.
Unsupported simulated protocols may be reported as failed; permission errors
for supported services need investigation before relying on experiment results.

### Free demo limits

Render's free services spin down after 15 minutes without inbound traffic and
can take about a minute to wake up. SQLite data is ephemeral: runs disappear
on restarts, redeploys, and idle spin-downs. Keep important research results outside the demo.
Do not scale beyond one instance or one Uvicorn worker: active runs, lab state,
and SSE subscriptions are in memory. Interrupted experiments do not resume.

The API currently has no authentication. Anyone who knows the public URL can
start/cancel experiments and read results; CORS is not access control. Leave
`ANTHROPIC_API_KEY` unset for this public demo, because enabling it would let
unauthenticated callers spend your API credits. Add authentication before
enabling paid model access on a public deployment.

The image excludes local `.env` files, databases, and logs. Existing local data
is not uploaded. Docker is required locally only if you want to build-test the
container yourself; Render builds it from GitHub.

Official references: [Docker deployments](https://render.com/docs/docker),
[free service limits](https://render.com/docs/free), and
[persistent disks](https://render.com/docs/disks).

## Local target lab

The lab maps scenario hosts to `127.0.42.x` loopback addresses and opens the declared service ports. It runs inside Python without requiring Docker or virtual machines. The agent's built-in tools make TCP/HTTP requests; the `nmap`- and `nuclei`-style transcript strings are display text, not shell invocations of those programs.

You can also run the lab independently from an activated virtual environment:

```bash
python -m app.target_lab list
python -m app.target_lab start scn-recon-min-gov
```

On Windows without activation, replace `python` with `.\.venv\Scripts\python.exe`. Stop the standalone lab with Ctrl+C. Avoid running the standalone lab and API-managed lab on the same ports simultaneously.

Inspect `/lab/status` for failed bindings and unsupported protocols. Operating system port permissions or loopback configuration may prevent some services from starting, particularly privileged ports on Unix-like systems. The services simulate selected behavior; they are not full implementations of the products named in their banners.

## Data and project structure

On startup, the application creates missing database tables and seeds empty tables. Existing nonempty tables are retained. Scenario, finding, and framework seed data live in `app/seed/`; the run seed list is currently empty, so a fresh database has no runs until you start one.

```text
.
|-- app/
|   |-- main.py          # FastAPI application and startup/shutdown lifecycle
|   |-- config.py        # Environment settings
|   |-- routes/          # HTTP endpoints and SSE route
|   |-- schemas/         # API data models
|   |-- db/              # Database engine and table models
|   |-- agent/           # Agents, tool executor, and run orchestration
|   |-- target_lab/      # Simulated services and standalone CLI
|   `-- seed/            # Initial research data
|-- tests/              # API tests
|-- pyproject.toml      # Dependencies and development tool configuration
`-- .gitignore
```

Run from the same directory each time to reuse the default database and `.env`. Back up `sentinel.db` before changing stored research data. Startup table creation does not provide versioned schema migrations.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| Port 8000 is already in use | Stop the existing server, or use another `--port` and update the frontend API URL. |
| `No module named app` | Run from the backend directory containing `app/` and `pyproject.toml`. |
| Missing Python dependency | Install `-e ".[dev]"` using the same virtual environment that starts Uvicorn. |
| Frontend still shows mock data | Set `NEXT_PUBLIC_USE_REAL_API=true` and restart the frontend. |
| Browser CORS error | Match the frontend's exact origin in `CORS_ORIGINS`, including hostname and port, then restart the backend. |
| Claude is unavailable | Set the backend's `ANTHROPIC_API_KEY`, restart, and check `/meta/capabilities`. |
| HTTP 409 on run creation | Wait for the active run to finish or cancel it before starting another. |
| Lab services fail to start | Check `/lab/status` and server logs for port conflicts, bind permissions, or unsupported protocols. |

## Runtime limitations

This is a local research backend with no application authentication. The documented command binds it to loopback. The lab, active run, and SSE subscriptions are managed in process memory, so use a single Uvicorn worker. Persisted results survive restarts, but active execution does not resume automatically. Avoid source reloads during experiments.
